# Phase 1: Foundation — Engine Labs company operating system

Generated by executing `docs/plans/phase_0_foundations_plan.md` §22 after the phase-0 Project Lead gate (CONDITIONAL) and T0-13 reconciliation (validators: preflight READY, validate-launch 79 files, validate-agent-config, 17/17 tests — 2026-09-10T18:33:59Z). This plan is documentation; nothing in phase 1 is implemented until this file exists and the entry criteria in §3 hold.

## 1. Objective

Build intake implementation phase 07: the smallest coherent repository per D-01 that lets the founder sign in to a Tauri 2 desktop shell ported from the recorded Papership `/cc-org-dash` reference, create priorities and plans against a server-side work ledger, start a persisted background job orchestrated by DBOS, close the desktop, and reconnect to the job's streamed status — with identity, the Founder seat, server-side grant checks, the 43-row capability registry service, source references, secure token handling, a seeded development environment and ordinary-language empty/error states. Phase 1 also lands every Security finding gated at phase 1 (`docs/roadmap.md` §5) and the supply-chain baseline, and closes with a Security re-review, UI/UX fidelity and accessibility review, and the Project Lead gate G1.

Phase 1 produces local, runnable code and a development Compose stack. It installs no Hermes runtime, enables no side-effecting toolset, and performs no commit, push, deployment, DNS, billing or publication.

## 2. Relation to project end-state

End-state (intake "Final result", `docs/product.md` §9): the founder signs in, plans work, runs persisted cloud jobs, reconnects to them, and completes a real Engine Labs change through the governed development loop; the registry shows truthful statuses; commercial, connector and mobile scope stays `planned`.

Phase 1 delivers the substrate for R1-ACC-1…5 at development-build level (packaged signing is phase 3), creates the contracts, authority model, job persistence and desktop shell that phase 2 (intake phase 08, development loop) binds Hermes and GitHub into, and encodes the fail-closed worker configuration (AUTH-25) that phase 2's interception spike SP-1…SP-7 must satisfy before any side-effecting toolset is enabled. R1-ACC-6…9 (loop, assistant sessions, agent-run detail with live usage, contract tests at the runtime boundary) are phase 2. R1-ACC-10…15 are phase 3.
